# 排除規則：哪些字串不該被當成注音誤打

因為 26 個字母全部落在注音鍵上，很多正常英文／技術字串也「看起來像」注音按鍵。
若不排除，這個 skill 會熱心到把 `npm run dev` 翻成中文，造成實際傷害。
`scripts/decode_bopomofo.py` 的 `exclusion_reason()` 實作了以下規則。

## 直接跳過（硬排除）

| 規則 | 原因 | 例子 |
|------|------|------|
| 含大寫字母 | 注音誤打一定是小寫；大寫多為 camelCase／常數／hash | `GitHub`、`API_KEY`、`aB3f9` |
| 含注音鍵盤以外字元 | `@ # $ % & * + = _ ?` 等，或中日韓字 | `user@host`、`a=1`、`你好` |
| 含 `://` | 網址 | `https://x.com` |
| 路徑樣式 | 開頭 `~ . /`、含 `//` 或 `\`、drive letter `C:` | `./src/app.py`、`C:\tmp` |
| CLI flag | 開頭 `-` 或 `--` | `-m`、`--verbose` |
| 純數字／版本號 | 全是數字與 `.`／`,` | `2024`、`3.14.1`、`721` |
| 檔名樣式 | `name.ext`（副檔名 1–6 字） | `config.py`、`index.tsx` |

程式碼區塊（``` ``` ```）與行內 code（`` ` ``）在進入分析前就被遮罩掉，不會被碰。

## 軟判斷（靠信心分數）

通過硬排除後，還要「能完整切成合法國語音節」才算候選。再用信心分數分級：

- **含數字**（聲調 3/4/6/7 或韻母 8/9/0）＋能切音節 → 強訊號，通常 `high`。
  英文單字幾乎不會在字中夾數字，這是最好用的判準。
- **純字母**（無數字）→ 本質曖昧。`npm`、`git`、`html`、`css` 都能硬切成音節，
  所以上限壓在 0.60，永遠不會靜默觸發；交給有上下文的 LLM 判斷。

## 已知會被正確放過的技術字串

`npm`、`git`、`http`、`html`、`css`、`run`、`dev`、`commit`、`install`、
`fix`、`config.py`、`./src/app.py`、`--verbose`、`2024.1`、`issue721`、
`GitHub`、`user@host` …等（見 `tests/cases.tsv` 的反例集）。

## 已知限制（phase 2 再處理）

- **英文與注音黏在一起沒空白**（如 `fixsu3cl3a8`）目前以整個 token 判斷，
  可能整段被放過。之後可加子字串切分。
- **純字母的真注音誤打**（如 工=`ej/`，全一聲無數字）會被壓成 `low`，
  可能需要上下文才救得回來。加入離線詞典（phase 2）後可大幅改善。
